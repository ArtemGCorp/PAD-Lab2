# PAD · Лабораторная работа №2 — UI-генератор билетов

Десктопное приложение на **Go + [Fyne](https://fyne.io)**. Выдаёт студенту экзаменационный
билет и сразу записывает результат в `results.xlsx`.

| Вход | Выход |
|---|---|
| `students.xlsx` — лист = группа, A = Фамилия, B = Имя, данные со строки 2 | `results.xlsx` — журнал, только дописывается |
| `tickets.docx` — `Билет N` + нумерованные вопросы `N. текст` | `lab2.log` — ошибки парсинга и записи |

## Запуск

```bash
go run ./cmd/sampledata   # создать демо students.xlsx и tickets.docx (уже лежат в репозитории)
go run .                  # запустить приложение
```

Пути можно переопределить: `go run . -students path.xlsx -tickets path.docx -results out.xlsx`.

Требования: Go 1.26+, на macOS — Xcode Command Line Tools (Fyne использует cgo/OpenGL).

## Как работает

1. При запуске первый список заполняется именами листов `students.xlsx`.
2. После выбора группы второй список заполняется студентами в формате «Фамилия Имя».
3. Кнопка «Сгенерировать билет» активна только когда выбраны и группа, и студент.
4. Окно результата: «Ваш билет № N» и вопросы билета. **ESC** закрывает только это окно.
5. Строка добавляется в `results.xlsx` сразу (tmp-файл → fsync → rename, старые строки не меняются).

**Назначение билета.** Если студент (группа + фамилия + имя) уже есть в журнале — берётся номер из
**первой** записи, новая строка пишется с «Повтор = да». Иначе — случайный билет из корректных
билетов `tickets.docx`, «Повтор = нет». Журнал хранит полную хронологию всех выдач.

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Группа | Фамилия | Имя | Номер билета | Дата и время | Повтор (да/нет) |

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет `students.xlsx` / `tickets.docx` | Сообщение в окне и в статусе, кнопка «Перечитать файлы» |
| Пустая группа | Второй список пуст, кнопка неактивна |
| `results.xlsx` открыт в Excel (`~$results.xlsx`) или нет прав | Диалог «Файл занят» с кнопкой «Повторить» |
| Билет с < 3 вопросов, нераспознанный заголовок, дубль номера | Билет пропускается, запись в `lab2.log`, работа продолжается |

Демо `tickets.docx` специально содержит два битых билета (11 и «двенадцать»), чтобы это было видно.

## Тесты

```bash
go test ./...
```

| Пакет | Что проверяется |
|---|---|
| `internal/tickets` | Парсинг Word: `N.`/`N)`, автонумерация Word, пропуск коротких и битых билетов, дубли |
| `internal/students` | Группы = листы, студенты по группе, пустые группы, поиск только внутри группы |
| `internal/results` | Создание с шапкой, дописывание, блокировка Excel, поиск первой записи |
| `internal/assign` | Идемпотентность: повторный выбор → тот же билет + новая строка «да» |
| `main_test.go` | 12 UI-тестов через `fyne/test`: группы и студенты, активность кнопки, окно билета (номер, 3 вопроса, пометка «Новый»/«Повтор»), ESC и «Закрыть», хронология журнала, пустая группа, нет файлов → «Перечитать файлы», блокировка Excel и снятие блокировки |

### Наглядный запуск UI-теста

```bash
VISUAL=1 go test -run Visual -v .
```

Открывается настоящее окно приложения, и сценарий из 13 шагов выполняется в нём по очереди с паузами:
выбор значений, нажатия кнопок, ESC, ошибки. Название текущего шага видно в заголовке окна, каждый шаг
проверяется. Скорость меняется через `VISUAL_DELAY`, например `VISUAL_DELAY=2s`. Без `VISUAL=1`
этот тест пропускается, а остальные UI-тесты работают без окна.

Отрисовать окна в PNG (светлая и тёмная тема) для визуальной проверки:

```bash
LAB2_SCREENSHOTS=/tmp/shots go test -run Screenshots .
```
